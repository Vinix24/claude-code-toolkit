# Changelog

## 1.1.0

From four later cases, each of which added a search place to step 2.

- Step 2 also looks in the reader's own earlier work: a skill, a prompt or an earlier answer with the same mechanism.
- Names of skills, files or templates in the post or the image are searched literally on GitHub first. Such a list is often complete in one public repository.
- For a new vendor feature, the skill first reads what the feature does not deliver. That gap is often the hard part.
- Before raising an objection to the maker's work, the skill looks for the maker's own measurements.
- An analysis of an export is computed with code, with the deciding rule above every list. A model that only reads a table fills gaps with links that are not in the data.
- Same changes in `PLAK-PROMPT.md`.

## 1.0.1

- The last section is now called "De vastlegging" instead of "Het bonnetje": it records what was checked, and often says "nog te toetsen" or "niet gemeten".

## 1.0.0 (unreleased)

First version. The tone is helping, not unmasking.

- Handles comment gates and search requests.
- Checks first whether the promised thing already exists: in the post, from the maker, or as a product.
- Chooses the form before building: just buy it, paste prompt, skill, plugin, proof of concept or site.
- Every answer has the same eight sections, ending with a receipt to tick off after the build.
- Never copies the post; conditions are written in its own words.
- `PLAK-PROMPT.md` with the same steps for ChatGPT and Claude in the browser.
- A hard length limit: at most 1,200 words of running text, 600 for "use what exists". Prompts, code blocks and tables do not count. Added after a third test round produced 2,700 to 3,200 words.
- Points readers who want to make their own skill to Claude's skill-creator.
- Maps the reader's situation first: at most five questions before answering, and every prompt it hands out starts with questions about the situation of whoever runs it.
